# 公開版の検証範囲

この公開用コピーは個人の開発履歴を含めず、検証器の契約を独立して試します。
所有者が2026-09-29に承認した分離案に基づく変更です。元Repositoryの回答、Report、
実履歴の検証は非公開で保持し、公開版の成功へ読み替えません。

## 収録の決め方

配布コピーは開発Repositoryの指定Commitから、全Fileを次の区分へ割り当てた収録台帳に
従って書き出します。未分類のFileが1つでもあれば書き出しは失敗します。

| 区分 | 扱い |
|---|---|
| 配布する現行仕様・コード | 収録 |
| 合成試験入力 | 収録 |
| 表示義務があるライセンス | 収録（著作権・Unicode License・帰属表示を削らない） |
| 非公開の回答・履歴・監査 | 除外。非公開側で保持 |
| 要判断 | 除外。公開するにはOwnerの判断が必要 |

初回の新しい履歴は1 Commitで、作者・日時は固定値です。その後の公開版の保守履歴は初回Rootへ束縛して検査し、開発Repositoryの既存履歴は含めません。

## 試験が確かめるもの

| 対象 | 公開版が確かめるもの | 証明しないもの |
|---|---|---|
| Consumer / Provider履歴 | 実監査器で生成した合成Git入力を実検証器が受理し、欠落・改変を拒否 | 個人の過去Reportの実再現 |
| 設計と回答の束縛 | 合成設計・合成回答のHashとGit入力の一致、差替えの拒否 | 元所有者の回答の正当性 |
| 現行監査 | 明示的なcurrent-canon指定のCLIと直接呼出しの一致 | 過去回答の新しい設計への承認移転 |
| Block Recordの規則 | 正規の検査器が受理した合成Record一覧で、後継連鎖・解消根拠の規則が働き、崩した一覧を落とす | 開発中に記録された個々の塞がりと、その判断の内容 |
| Providerの具体値 | 正規の生成器で組んだ合成の回答Packageを、記録器・ローカルUI・準備状況の監査器が同じ規則で検査・拒否 | Ownerが記録した具体値、実Providerの設定 |
| 回答Packageが無い初期状態 | 記録値の再検査は `OWNER_VALUES_UNSET` で止まり、UIは未設定として扱う。壊れたFileは未設定に見せない | — |
| 設計参照の現行性 | 公開物の許可表だけで検査し、表に無い古い参照を新規として落とす | 非公開記録の許可表 |
| Release署名の信頼根 | 信頼する鍵を宣言していない `ci/allowed-signers` を `UNTRUSTED_REVIEW_ONLY` として拒否 | 元所有者の鍵・承認。配布物はどの鍵も信頼しない |
| Secret Scanの分類 | `.gitleaksignore` の各位置の分類根拠を現在の行から再計算し、行が変われば失敗 | 外部の資格情報でないことの数学的証明 |
| 個人・環境情報の開示検査 | 検出を所在と根拠で区分し、値を出力しない | 検査Toolが扱わない種類の情報が無いこと |

`run-checks.sh` の `synthetic_consumer_contract` と `synthetic_provider_contract` は
`SYNTHETIC_CONTRACT_VERIFIED` を出力します。通常の履歴検証器は変更していません。
個人の履歴入力がないまま通常の検証器を実行した場合は引き続き拒否されます。
`tests/` 全体を実行し、欠落・改変などの詳しい拒否条件も検査します。

保存済みの回答・監査記録・Block Recordそのものの事実（値が未入力のまま止まっている、
記録のHashが一致する等）は非公開側の試験（`tests/private_history/`）が確かめ、
このコピーには含めません。一般的な拒否条件は削除・Skip・緩和せず、合成入力で残しています。

合成データは一時Directoryに生成します。実Owner回答の記録や利用者設定として保存しません。
公開版のLOCAL_OKは、GitHub CI・実Provider接続・Runtime GO・Human Releaseの成立を意味しません。
公開用初期設定は単一SQLite DBに保存するWorkbenchの選択設定です。設定保存は送信・適用を承認しません。
全検査が通っても、公開の可否はOwnerが `docs/PUBLICATION.md` の条件を確認して判断します。
