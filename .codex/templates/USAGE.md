# multi-harness の使い方

作成: 2026-09-30 / 更新: 2026-10-06 / 作成支援: Codex, Claude Code。ローカルSource Previewの手順です。初回導入は[はじめての起動](../../docs/QUICKSTART.md)から進めてください。

## 初回は準備Toolを使う

[実CLIの初回手順](../../docs/TRY-REAL-CLI.md) で、まだ存在しない専用Directoryに隔離Worktree・DB/CAS・実CLI Profileを準備できます。以下の手動起動は、既に自分のWorktreeとProfileを用意した場合の手順です。準備Toolは既存データを上書きせず、失敗時にMockへ切り替えません。

## 起動する

WSL2/LinuxのFilesystemで作業します。Windows側や `/mnt/` は使用できません。
依存の導入はREADMEを参照してください。CLIを使う場合は導入・ログインが別途必要です。ChatGPT連携はCLIの導入を必要としません。
ここでは新しい専用DBと隔離Worktreeを使用します。認証情報をRepositoryへコピーしないでください。

```bash
export PYTHONPATH=src
.venv/bin/python -m harness.presentation.cli workbench-profile --out "$HOME/harness-demo-profile.json"
.venv/bin/python -m harness.presentation.cli ui \
  --database "$HOME/harness-demo-state/state.sqlite3" \
  --artifact-root "$HOME/harness-demo-state/cas" \
  --repo-root "$PWD" \
  --workspace "$HOME/harness-demo-worktree" \
  --cli-runtime-profile "$HOME/harness-demo-profile.json" \
  --workspace-label "demo-worktree"
```

`harness-demo-worktree` は事前に作成したLinux上の隔離Git Worktreeを指定します。
DB/CASの親Directoryも事前に用意してください。起動時に表示されたローカルURLを開きます。
Providerの能力検査で拒否された場合は、理由を確認してください。ログインだけでは制限を満たしたことになりません。
画面を外部公開したり、他者へ操作Tokenを渡したりしないでください。

## 文章・Markdownをつくる

1. 「AIワークスペース」で、文章・要約・企画・比較・レビュー・相談の用途を選びます。
2. AI・モデル・推論レベルを選び、「AIへの依頼」を書きます。参考資料・メモは任意で貼り付けます。ファイル選択は不要です。
3. 成果物の形式を選び「送信内容を確認」を押します。この時点ではAIに送信していません。
4. 表示されたJSONに、依頼・参考本文・選択した会話が含まれていることを確認し、送信を承認します。利用枠を消費する場合があります。
5. 結果は履歴に保存されます。内容を確かめ「文章をコピー」または「ファイルを保存」で使います。Markdownは .md、文章は .txt です。
6. 「この会話で続きを依頼」を押し、AIや用途を切り替えて続けられます。参考本文と以前の成果物も選択した履歴に入ります。

文章成果物はファイルの置換ではありません。適用ボタンや適用承認はありません。
文字として表示するため、HTML・スクリプト・Markdownに含まれる命令は実行しません。
参考本文はUTF-8で既存の対象本文上限まで、依頼は既存の依頼上限までです。
JSONを含む送信全体と履歴にも上限があります。超過時は省略して送信せず、画面で停止理由を示します。
名前などの個人情報や秘密情報を貼り付けないでください。スキャナが検出した場合は送信を拒否します。
提供資料に基づく草案です。根拠・日付・専門的な判断は確認してください。Web調査、Word/Excel/PDF生成は未実装です。

## 設定とファイル編集

1. AIワークスペースで「コード・ファイル編集」を選び、Provider、モデル、対応する推論レベルを選びます。候補は導入CLIのProfileに基づきます。未対応の推論値は拒否します。
2. 次回も使う場合は設定保存の確認欄にチェックし、保存します。同じDB・Workspaceで再起動すると読み込まれます。保存だけではCLIを起動せず、送信・適用を承認しません。
3. 対象ファイルと依頼を入力し、送信内容全体を確認します。実送信にはProviderの利用枠を消費する可能性があります。
4. 送信を承認し、生成された差分を確認します。適用は別に承認します。
5. 複数選択時は1ファイルずつ確認・適用し、次へ進みます。生成コードを自動実行する機能ではありません。

保存競合時は再読込みして、最新の設定を確認してから保存してください。通信失敗時の自動再送は行いません。
保存設定を変えても、既に確認中のPlanは変わりません。別設定を使う場合は新しい依頼を作成します。
元所有者の回答Packageが無い初期状態は「未設定」と表示します。古いChat設定とWorkbenchの選択設定は別です。

## 更新・復旧

本変更は状態DBをversion 14へ移行します。更新前に既存のBackup手順でDBとCASを保全してください。
古いコードへ戻す場合はサーバーを停止し、更新前の対応するDB/CASコピーを別Directoryへ復元します。
表を削除してversion番号だけを戻さないでください。送信結果不明の依頼は再送せずReceiptとJournalを確認してください。

## 検証の意味

実ブラウザー試験の生成部分は合成CLIと境界Probeの代役を使います。実Provider接続成功の証明にはなりません。
LOCAL_OK、GitHub CI、実Provider接続、Runtime GO、Human Releaseは別の判定です。
GitHubへの公開は、Ownerが公開前確認（docs/PUBLICATION.md）の条件を確認して承認するまで行わないでください。


## 受付と復旧

この欄は、途中で止まった処理の残存状態を整理し、新しい依頼の受付を再開するためのものです。
通常の「OPEN＝受付中」なら操作は不要で、コード編集を始められます。
停止中は「現在の状態を確認」→整理の確認・承認→再確認→受付再開の確認・承認の順に進みます。
実行中・結果不明・履歴不整合などの理由が残る場合は、表示された理由を解消してから再確認します。無理に有効化しません。

既定起動はこの運用欄だけ参照専用です。運用操作を使う場合は、次で現在のLinux利用者の識別子を確認します。

~~~bash
.venv/bin/python -c 'import os; print("local-uid:" + str(os.getuid()))'
~~~

表示された識別子を、既に準備したDirectoryに対する起動コマンドへ指定します。
以下の <表示された識別子> は実際の出力に置き換えてください。

~~~bash
.venv/bin/python tools/prepare_preview.py start --directory "$HOME/your-prepared-preview" --operator-auth-session <表示された識別子>
~~~

既存Serverは端末で停止してから再起動し、ブラウザーを再読み込みします。
DB/CAS/workspace/profileを作り直さないでください。OSの別利用者の識別子は拒否されます。
これはローカル単一利用者の操作許可で、組織的な本人確認や承認の省略ではありません。

## 接続設定・会話とContext

「接続・生成の設定」は実CLIの検証状態と現在の選択を表示します。AI・モデル・推論値の変更と保存は、リンク先のコード編集欄で行います。
開閉できる設計情報は従来の業務フロー用で、実CLIの設定と別です。公開版に旧Owner回答をコピーして有効化しないでください。

「会話・資料の保存」は依頼の下書きや参考情報をローカルに保存します。保存だけではAIの返答は発生しません。

1. 新しい会話を作り、通常の本文はUSER_TASKで保存します。
2. 確認用コピーを作ります。本文を追加した後はコピーを作り直します。
3. コード編集でAIとモデルを選び、「確認用に使う」を押すか、確認用モデルIDを自分で入力します。
4. 予算・返答用の量・上限・期限を確認し、「情報量と選択結果を確認」を押します。実モデルの上限を自動保証する機能ではありません。
5. コードを生成する場合は、会話を依頼欄へコピーします。入力済みの依頼を上書きせず、本文取得不可を黙って省略しません。コピーは外部送信ではありません。
6. 対象ファイルとAIの設定を選び、コード編集の完全な送信内容を確認・承認します。差分適用も別に承認します。

この「会話・資料の保存」欄は、ローカルの保存とContext確認に使います。実AIに文章や相談を依頼する場合は「AIワークスペース」を使います。CLIまたはChatGPTログイン連携を選び、ファイル指定なしでも生成できます。保存しただけでは外部へ送信しません。


## 同じ会話を別のAIへ引き継ぐ

コード編集欄の「会話を引き継いで続ける」で、続ける会話を選びます。
依頼を一度作ると、その会話が次の依頼の引き継ぎ先になります。
AI・モデル・推論レベルを切り替えて、次にしてほしいことを入力してください。
手で過去の依頼を貼り直す必要はありません。

1. 「引き継ぐ会話と生成結果を見る」で、過去の依頼と生成コードを確認します。
2. 今回編集するファイルと、次の依頼を選びます。
3. 「送信内容を確認」で、今回の依頼・現在のファイル・引き継ぐ会話全体を確認します。
4. 送信を承認します。以前の送信承認は使い回しません。
5. 生成された差分を確認し、別の承認で適用します。

保存した会話から始める場合は、「会話・Context」の詳細で
「この会話全体を引き継いでコード編集」を押します。
利用者の依頼だけでなく、保存されているすべての役割の本文を引き継ぎます。
入力済みの依頼欄は上書きしません。保存や会話選択だけでは外部へ送信しません。

引き継ぐものは、このHarnessで保存した本文、CLIへの各依頼、生成コード、
当時の変更前後と差分、適用済み・未適用・失敗の状態、実際の適用確認結果です。
コードの試験を自動実行したとは扱いません。検査の説明や残作業は、
保存会話へ追記して次の依頼に渡せます。

ブラウザーやアプリを再起動した後も、保存した会話を選んで続きを依頼できます。
アプリを更新した場合は、新しい送信Planと承認を作ります。古い承認は流用しません。

- 元の会話や生成案が確認後に変わった場合：新しい依頼を作り、内容を再確認します。
- 処理中・承認済み・結果不明の場合：該当する依頼を完了または復旧してから続けます。
- 送信上限を超える場合：全履歴を黙って省略しません。「最近の履歴」を明示選択し、必要な制約を要点欄へ記入して作り直せます。それでも入らない場合は「新しい会話」を始めます。
- 「新しい会話」は引き継ぎ先を解除します。過去の保存データは削除しません。

Codex・Claude Code・Geminiの各アプリ本体にある会話や、非公開の思考過程は自動で取り込みません。
既存のCLI出力契約はコードの提案です。Harnessが受け取っていない回答を補って作ることはありません。

## ChatGPTログイン連携と履歴の送信範囲

ChatGPTの契約を使う場合は、コード編集欄の「ChatGPTでログイン」から公式ページで連携を許可します。利用可能なモデルをアカウントから取得し、その候補から選びます。CLIの導入やAPI Keyの入力は不要です。公式Responses APIへOAuthで送信する方式で、Web版の既存会話を取得する機能ではありません。

送信内容を確認してから生成を承認し、生成後は別に差分の適用を承認します。ログイン・モデル選択・設定保存だけでは生成しません。認証トークンはサーバーのメモリーだけに保持し、再起動後は再ログインします。切断の遠隔確認に失敗した場合は、画面の案内に従ってChatGPT設定でも確認してください。

「全履歴」または「最近の履歴」を選べます。最初の依頼と保存したsystem・developerメッセージを残し、古い本文を選ばない場合は元のArtifactを保持して、除外理由と参照Hashを記録します。「必ず伝えたい要点・制約」は毎回の送信内容へ含めます。自動のAI要約は呼び出しません。結果不明や改変は、選択範囲の外にあっても停止します。

容量は実際のUTF-8 Bytesで表示します。モデル固有のトークン数と文脈上限は未計測です。このChatGPT連携では出力トークン上限を指定できず、ローカルの受信容量・時間上限は課金上限になりません。[ChatGPTの利用枠・クレジット設定](https://chatgpt.com/settings/usage)で確認してください。実アカウントでのログイン・生成は、合成応答による検査と別の確認です。

ChatGPTだけを使う起動例（Worktreeは上の手順で準備してください）:

```bash
PYTHONPATH=src .venv/bin/python -m harness.presentation.cli ui \
  --database "$HOME/multi-harness-demo/state/state.sqlite3" \
  --artifact-root "$HOME/multi-harness-demo/state/cas" \
  --repo-root "$PWD" \
  --workspace "$HOME/multi-harness-demo/worktree" \
  --workspace-label "demo-worktree"
```

CLIを使わない場合も、Linux上の隔離Git Worktreeと、その外のDB/CASを用意します。起動は既存のuiコマンドで、--workspaceを指定し、--cli-runtime-profileを省略できます。CLIも併用する場合は従来どおりProfileを指定します。Workspace自体を省略するとコード編集は未設定のままです。

この拡張は状態DBをversion 14へ移行し、登録情報だけを同じDBに保存します。Access/refresh/ID tokenは保存しません。更新前のDB/CASを保全してください。旧コードへ戻す際はサーバーを停止し、対応する更新前のDB/CASコピーを別Directoryで使います。表やversion番号だけを戻さないでください。

## ChatGPTで話した知識を引き継ぐ

AIワークスペースの「ChatGPT Webの会話・メモリーを取り込む」から、会話JSONやコピーしたメモリーを選んで確認・保存できます。「続ける会話」で保存資料を選び、CLIへの送信内容を確認してください。ログインだけでWeb版の知識が共有されるわけではありません。[詳しい手順](../../docs/CHATGPT-KNOWLEDGE.md)を参照してください。
